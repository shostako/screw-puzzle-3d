# ロードマップ

仕様は [SPEC.md](SPEC.md)、技術や見た目の判断は [DECISIONS.md](DECISIONS.md)。

進め方: 1スレッドで1項目を進める。終わったら（PR の ci が成功して master にマージしたら）チェックを付け、その項目の「分かったこと」を書き足す。上から順に進め、前の項目が master に入るまで次を始めない。

どの項目でも守ること:

- ゲームのルール（ねじが外せるか、箱とスロットの動き、クリアと詰み、盤面が解けること）はテストで守る。テストは `npm test` から走り、CI（`scripts/ci.sh`）が毎回回す。
- 画面が変わる PR には、ヘッドレスのブラウザで撮ったスマホ縦画面のスクリーンショットを付ける。
- 外部の読み込み（CDN など）はしない。ライブラリは npm で入れてビルドに同梱する（Android アプリで、ネットが無くても動くように）。

## M2 ルールの核: 描画なしで1局を最後まで進められる

## 分かったこと

各項目を終えたスレッドが、次の項目の役に立つことを書き足す。

### M1 で分かったこと

- 道具: three.js + Vite + Vitest（理由は DECISIONS.md）。`npm run build` で `dist/` に出る。`base: './'` なので Pages のサブパスでも Capacitor でもそのまま動く。
- 指の判定は `src/gesture.js` の `createGesture()`。down/move/up/cancel に座標と時刻を渡すと `rotate` / `zoom` / `tap` の出来事を返す。M4 でねじを外すときは `tap` だけを使えば、ドラッグ中に外れることはない。
- 回転の計算は `src/view.js`（three.js に依存しない）。立体の `quaternion` にカメラから見た軸の回転を左から掛けている（`premultiply`）。
- 仮の立体は `src/placeholder.js`。M3・M4 で本物の盤面に置き換える。
- スクリーンショット: `npm run build && npm run screenshot [-- 出力先]`。390×844（DPR 2）のタッチ端末として開き、CDP でタッチを送ってドラッグ・ピンチする。場面を足すときは `scripts/screenshot.mjs` の `shots` に追加する。描画の完了は `window.__app.rendered` で待つ。ヘッドレスの WebGL は `--use-angle=swiftshader` で描ける。
- PR に貼るスクリーンショットは `docs/screenshots/<項目>/` に置いてコミットし、コミットの SHA 付きの URL で参照すると、ブランチが消えても表示が残る。
- `scripts/ci.sh` は build の後に `scripts/check-dist.mjs` で `dist/` の外部 URL 参照（HTML の src/href、CSS の url/@import、JS の import()/fetch）を検査する。
- favicon が無いとブラウザが `/favicon.ico` を取りに行き 404 になるので、`index.html` に `data:` の空アイコンを置いている。

### M2 で分かったこと

- ルールは `src/rules.js`。盤面は `{ plates: [{ id }], screws: [{ id, plate, color }], queue: [色...] }` の形で、`newGame(level)` で始め、`removeScrew(state, id, isBlocked)` で1手進める。状態は毎回新しいオブジェクトで返り、前の状態は書き換えない（戻る・ヒントの探索でそのまま使える）。
- `removeScrew` は `events`（`toBox` / `toSlot` / `plate` / `boxFull` / `boxSpawn` / `slotToBox` を起きた順に）を返す。M4 の描画はこれを順に再生すれば、ねじが飛ぶ先・箱の入れ替わり・板の落下を追える。板の状態は `plateState(state, id)`（fixed / hanging / fallen）。
- 外せない理由は `checkRemove` が返す `gone` / `blocked` / `full`。`blocked` のときは震えて拒否、`full` のときは待機スロットを光らせる（2D 版と同じ）。
- 隠れ判定は `isBlocked(screwId, state)` を外から渡す。テストでは「このねじはこの板たちに隠れている、板が落ちれば見える」という表（`coverBlocker`）で代用している。M3 の 3D 判定も同じ形の関数にすれば、そのままルールにつながる。ぶら下がった板も隠し続ける扱いは、判定側で決める。
- 詰みは「外せるねじが1本も無い」で決めている。2D 版の「スロットが満杯で入れられるねじが無い」は、最上階層のねじが必ず見えている 2D 版ではこれと同じ。3D ではスロットに空きがあっても全部隠れていることがありうるので、一般の形にした。板が揺れている間は詰みを決めない、という時間の扱いは M5 で物理側に持たせる。
- 盤面は `validateLevel` が「色ごとのねじ = 箱の数 × 3」などを検査し、合わなければ例外にする。M6 の生成器の出力もこれを通す。
- 2D 版の飛んでいる途中・フタが閉まる途中などの時間は持たず、1手で箱の入れ替わりまで済ませる。移しただけで満杯になった箱は、その場で消えて次の箱が出る（連鎖する）。

### M3 で分かったこと

- 盤面の形は `src/board.js` の冒頭に書いた形。M2 の盤面に、板の `size`（または凸の `outline`）・`thickness`・`position`・`rotation`（Euler XYZ）か `quaternion`、ねじの `position`（頭の中心、板の表面上）・`dir`（抜ける向き）を足しただけなので、`newGame` にそのまま渡せる。板は局所の xy 平面の厚板で、法線が局所 z。
- ルールに渡す隠れ判定は `blockerFor(level)`。中身は `coverMap(level)`（ねじごとに隠している板の表、盤面ごとに1回計算）で、M2 のテストの `coverBlocker` と同じ形になっている。
- 姿勢が変わる場合（M5）は `sweepHits(level, screwId, { poses })` に `poses[板の id] = { position, quaternion }` を渡す。ねじは自分の板の初めの姿勢からの動きに合わせて動かして調べる。物理ライブラリの姿勢（四元数）をそのまま渡せる。
- 盤面の形の検査は `validateBoard`（ねじが板の表面の上・輪郭の内側にあり、抜ける向きが外向きの法線か、輪郭が凸か）。M6 の生成器の出力もこれと `validateLevel` の両方を通す。
- 固定の盤面は `src/levels/box.js` の `BOX_LEVEL`: 外寸 6 の箱（6枚）＋中の仕切り＋天板の上の札、ねじ 21 本・4色・箱 7 つ。始めに隠れているのは4本（仕切りの3本と、札の角が 0.09 かかった天板の1本）。M4 はこれを描けばよい（外寸 6 なので、M1 のカメラ距離・仮の箱の大きさとは合わせ直す）。
- この盤面は易しく、ランダムに外しても詰まない。到達できる局面は 300 万を超えるので、M6 の解ける保証の探索は、全部を数える形ではなく手順を1つ見つける形（と枝刈り）にする必要がある。
- 隠れ判定の正しさは、軸に平行な場合の正解の式との乱数比較（`test/geom.test.js`）と、同じ回転で全体を回しても答えが変わらないことで確かめている。

### M4 で分かったこと

- 画面のつなぎは `src/main.js`、盤面から three.js の立体を作るのは `src/scene.js` の `buildBoard(level)`（板は輪郭を押し出した Mesh、ねじは色の丸頭＋十字の溝の Group で `userData.screwId` を持つ）。1局の進行は `src/game.js` の `createGame(level)`（`tap(id)` が `reason` / `events` / `status` を返す。クリアか詰みの後は `over`）。描画に依存しないのでテストできる。
- 箱とスロットの表示は DOM（`#boxes` / `#slots`）。`hudOf(state)` で表示の形を作り、`applyEvent(hud, ev, level)` で removeScrew の出来事を1つずつ当てて演出の途中を見せる。出来事を全部当てると外した後の `hudOf` と一致することを、ランダムな 200 局でテストしている。演出を変えるときもこの一致を崩さない。
- ルールの状態はタップの瞬間に進め、演出は後から出来事の列を再生する（続けてタップすると再生を速める）。やり直しは `generation` を進めて古い演出を捨てる。
- ねじの選び方: まず光線で一番手前に当たったものを見て、ねじならそれ。板などに当たったら、画面上で 24px 以内の見えているねじ（`src/pick.js` の `nearestScrew`）。板の輪郭線と、板にめり込んだ軸は `raycast` を空にして当たり判定から外している（Line の当たり判定は太すぎる）。
- ねじ0本の板は `scene.attach` で立体の回転から外し、世界の下（画面の下）へ落として消す。M5 で物理に置き換えるときは、この `dropPlate` と、`tapScrew` の中の `plate` の出来事の扱いを差し替える。ぶら下がり（1本）の板は今はその場に残る。
- 外寸 6 の箱は、カメラ距離 19（寄り引き 12〜34）で縦画面の横幅に収まる。HUD の高さの分、`camera.setViewOffset` で立体を少し下に描いている。光線もこのずらしを含めて計算される（`setFromCamera` が射影行列を使うため）。
- スクリーンショットのスクリプトは、CDP のタッチでねじをタップして外れることと、隠れたねじが拒否されることを確かめ、`window.__app.legal()` で外せるねじを順に外してクリアまで進める。ページ側の目印は `window.__app`（`rendered` は演出の終わりも待つ）。
- `.gitignore` の `screenshots/` が `docs/screenshots/` まで無視していたので、`/screenshots/` に直した。

### M5 で分かったこと

- 物理は `src/physics.js`。`await initPhysics()` を1回してから `createPhysics(level)`。板は全部固定で始まり、`syncPlates(ph, state)` をルールの状態が変わるたびに呼ぶと、ねじ1本の板はぶら下がり（`hang`）、0本の板は自由になる（`release`）。始めからねじ1本の板もこれで扱える。`step()` は 1/60 秒進め、盤面の外へ落ちきった板の id を返す。板の状態は `mode(id)`（fixed / hanging / loose / gone）。
- 盤面の座標で解く。画面では毎フレーム、世界の下 (0, -1, 0) を立体の回転の逆で盤面の座標に直して `setDown` に渡す。向きが変われば止まっていた板も動き出す。
- 隠れ判定は `ph.blocker()`（今の姿勢 `ph.poses()` と、消えていない板 `ph.present()` で `sweepHits`）。止まった板・ぶら下がった板も隠す。詰みは `fixedBlocker(level)`（固定の板だけで判定、board.js）を `createGame` の3つ目の引数に渡して決める。物理なしのテストや M6 の探索は今までどおり `blockerFor` を使える。
- 固定の盤面は、外す順と向きによって「落ちた板が箱の中や縁に残って、ねじを隠し続ける」ことが普通に起きる。テスト（`test/physics.test.js` の `playBox`）とスクリーンショットのスクリプトは、外せるねじが無くなったら重力の向き（立体の向き）を6方向に順に変えて板を払い落とし、クリアまで進めている。M6 の探索で「回せば払える」を手順に入れるかは、ここを参考に決める（安全側に見積もるなら、動く板は盤面から消えるまで隠し続けるとみなす）。
- 箱の前板・横板は、ぶら下がるとすぐ底板の縁に引っかかって止まる（`test/physics.test.js` に場面がある）。ぶら下がりがよく見えるのは天板（立体を倒すと軸のまわりに振れて箱の中が見える）。
- Rapier の `body.sleep()` で眠らせた、継ぎ手つきの板を起こすと、継ぎ手が効かなくなって板が飛んでいった。落ち着いたかどうかは自分で数え（`QUIET_*`）、眠らせはしない。
- 同じ板のねじを、間を空けて1本ずつ外すと、間にぶら下がって回ってから落ちる。続けて外すとその場で落ちる。スクリーンショットの「札が天板の上で止まる」場面は、2本を同じタイミングで外している。
- 決定性は、同じシードで同じ操作をした2回の、全部の板の姿勢と落ちた順を JSON で比べて確かめている。画面ではフレームの間隔で刻みの数が変わるので、同じ指の動きでも同じにはならない（操作をした刻みの位置まで同じなら同じ）。
- スクリーンショット用に `window.__app.view(x, y, z, 距離)`（立体の向きを Euler で直接決める）と `plateModes()` を足した。`rendered` は物理が落ち着くのも待つ。
- dist の JS が約 5MB になった（Rapier の wasm を base64 で埋め込んでいるため）。M8 で、wasm を別ファイルにする版（`@dimforge/rapier3d-deterministic`）や読み込みの分け方を検討する。

### M6 で分かったこと

- 生成は `generateLevel(seed, opts)`（`src/generator.js`）。返り値は M3 の盤面の形そのもので、`meta` に `{ seed, kind, solution, tries, fallback, attempt }`。`opts` は `kind`（box / shelf / table）・`colors`（色の数、既定 4）・`labels`（札の数、既定 2）・`win` / `noise`（色の混ぜ方。大きいほど待機スロットを使う割り当て）・`budget`（探索の打ち切り）。M7 はステージ番号からこれらを決めればよい（今はシード 1〜300 で板 5〜11 枚、ねじ 12〜30 本。300 のうち 2 つは色の割り当てが最後の砦（順番どおりに箱が埋まる易しい割り当て）になった）。
- 解ける保証の隠れ判定は `safeBlocker(level)`（`src/safe.js`）。ルールの `isBlocked` の形なので `removeScrew` / `legalMoves` / `solve` にそのまま渡せる。後回しのヒントや「戻る」も、これと `solve(level, safeBlocker(level))` を途中の状態から呼ぶ形で作れる（`solve` は今は始めの局面からだけなので、状態を受け取れるように足す）。
- 探索は `solve`（`src/solve.js`）。深さ優先で1つ見つけたら終わり、行き止まりの局面は覚える。板を外し切る手（残り1本）を先に、ぶら下げる手（残り2本）を後に試すのが効いた（ぶら下がった板は届く範囲全部を隠すので、増やすと行き詰まりやすい）。局面の鍵の作り方に気をつける（'board' と 'box' の頭文字が同じで、最初は別の局面を同じとみなして解けないと答えていた）。
- 形が悪いと探索は打ち切りまで全部調べて遅くなる。板が互いのねじを隠し合う置き方（例: 上の棚板の下向きのねじと、下の棚板の上向きのねじ）は `peelable` で安く弾き、ねじだけ置き直している。
- 生成の速さ（手元の Node、シード 1〜300）: 平均 21ms、最悪 0.24 秒。スマホは数倍遅いとみて、最悪でも 1 秒程度。重いのは見積もりの抜け出す道の判定と、色の割り当てが外れたときの探索の打ち切り。テストは平均 100ms・最悪 1 秒で見張っている。
- 物理との突き合わせ（`test/safe-physics.test.js`）で、M5 の物理のバグが見つかった: 細長い板の当たりの形が実物より太り、壁の間の棚板が挟まって、どの向きに傾けても落ちなかった。`plateVertices` の縮め方を「辺ごとに同じ幅」に直した。手元で 1〜1000 のシードを再生し、見積もりが甘い場面は 0。
- 縮め方を直す前の突き合わせでは、机の天板がぶら下がったときに、軸のねじが幕板や脚にかすって隠れる場面も 2 つ（1〜200 のうち）出た。ねじのすぐ脇に別の板の縁がある置き方で、軸のわずかな傾き（ねじ1本で大きな板を支えるたわみか、太った当たりの形に押されたか）によるものと見ている（確かめてはいない）。直した後は 1000 シードで出ていないが、また出たら見積もりの円柱を少し太らせる。
- 画面は `?seed=番号&kind=種類` で生成盤面を開ける。`window.__app.solution` が見つけた手順で、スクリーンショットのスクリプトはこれを順に外し、物理で隠れていたら向きを変えて払い落としてからクリアまで進める。
