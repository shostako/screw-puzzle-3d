# 判断の記録

技術や見た目の判断と、その理由を1〜2行で残す。新しいものを下に足す。

- 2026-10-03 ルールは描画と物理から切り離した純粋なモジュールにする。ルールと解ける保証をブラウザ無しのテストで守れるようにするため（ROADMAP の M2）。
- 2026-10-03 盤面の生成器は、2D 版と同じく物理を安全側に見積もった探索で解ける手順を確かめる。実際の物理は揺らぐので、探索が楽観的だと解けない盤面が出るため（ROADMAP の M6）。
- 2026-10-03 3D 描画は three.js。WebGL の薄い層で、板・円柱・光の基本がそろい、物理ライブラリ（M5）とも組みやすい。Babylon.js より軽く、React 等の枠組みは要らない規模のため。
- 2026-10-03 ビルドは Vite（`base: './'`）。npm のライブラリを1つの JS に同梱でき、相対パスなので Pages のサブパスでも Capacitor の中でも同じ `dist/` が動くため。
- 2026-10-03 テストは Vitest。Vite と同じ ES モジュールの書き方のままブラウザ無しで速く回るため。
- 2026-10-03 立体の回し方は、カメラを固定して立体のほうをカメラから見た軸で回す（トラックボール式）。OrbitControls のような上下の制限が無く、裏も底も同じ指の動きで見られるため。
- 2026-10-03 タップの判定は、動き 10px 以内かつ 350ms 以内、2本目の指が触れた操作はタップにしない。回しているつもりでねじを外さないことを優先した値で、M8 で実機に合わせて詰める。
- 2026-10-03 スクリーンショットは playwright-core と既に入っている Chromium（`/opt/pw-browsers`）で撮る。ブラウザの取得を伴わず、ヘッドレスでも SwiftShader で WebGL が描けるため。CI では撮らない（ブラウザの用意が要るため）。
- 2026-10-03 ルールの状態は書き換えずに新しい状態を返す形にする。戻る・ヒント・解ける保証の探索が、状態を写して試すだけで済むため。
- 2026-10-03 詰みは「外せるねじが1本も無い」とする。3D では待機スロットに空きがあっても全部のねじが隠れうるため。2D 版の定義はこの特別な場合。
- 2026-10-03 隠れ判定は、ねじ頭の円柱を抜ける向きへ盤面の外まで掃き、板（凸多角形の厚板）との交わりを GJK で調べる。どちらも凸なので支持関数だけで厳密に判定でき、板が傾いても（M5）同じ関数で済むため。触れているだけは数えないよう、両方を 1e-4 縮めてから調べる。
- 2026-10-03 盤面の座標は three.js と同じ右手系・y が上、板の向きは three.js の Euler（XYZ）か四元数で書く。描画（M4）と物理（M5）へそのまま渡せるため。幾何の計算自体は three.js に依存させない（ブラウザ無しで速く回すため）。
- 2026-10-03 板が動かない間（M3・M4）の隠れ判定は、初めの姿勢で「ねじごとに隠している板」を1回だけ計算して表にし、そのどれかが落ちていなければ隠れているとする。ぶら下がった板はその場に残って隠し続ける扱い。
- 2026-10-03 箱と待機スロットは 3D ではなく画面の上の DOM で出す。回しても位置が変わらず、文字や色の表示が軽く、Android の WebView でもそのまま動くため。外したねじは画面上の位置から DOM の印を飛ばしてつなぐ。
- 2026-10-03 タップは光線で一番手前に当たったものを優先し、外れたら画面上 24px 以内の見えているねじを選ぶ。小さなねじ頭を指で狙えるようにするため。値は M8 で実機に合わせる。
- 2026-10-03 ルールの状態はタップした瞬間に進め、演出は出来事の列を後から再生する。速く続けてタップしても取りこぼさず、演出の途中でルールが食い違わないため。
- 2026-10-03 ねじは、色の付いた厚めの丸頭に濃い十字の溝。横から見ても頭の側面で色が分かり、上から見れば十字でねじだと分かるため。
- 2026-10-03 物理は Rapier の決定的な版（`@dimforge/rapier3d-deterministic-compat`）。浮動小数の計算順まで固定され、同じ操作で同じ結果になるのが保証されているため。凸包どうしの当たり・回転の軸（revolute）・すり抜け防止がそろい、wasm を JS に埋め込んだ版なのでネット無しでも Node のテストでも同じように動く。cannon-es は軽いが凸どうしの当たりが不安定で、決定性の保証も無い。大きさ（JS が約 5MB）は M8 で詰める。
- 2026-10-03 物理は盤面の座標で解き、立体を回すと重力の向きの方を回す（画面の下を盤面の座標に直して渡す）。固定の板は動かない体のままで、隠れ判定（board.js）の座標と姿勢をそのまま使えるため。回す速さによる慣性の力は無視する。
- 2026-10-03 ねじ1本の板は、そのねじの位置を通り抜ける向きを軸にした回転の継ぎ手でぶら下げる。ねじは板に垂直なので、板は自分の面の中で回る（2D 版と同じ動き）。
- 2026-10-03 ねじ0本の板は自由に落とし、盤面の外（盤面の半径＋板の大きさ）まで出たら消す。止まっている間は盤面に残り、ほかのねじを隠す。
- 2026-10-03 板の当たりの形は 0.03 縮めて角を 0.02 丸める。組んだ盤面では隣の板と面で触れ合っているので、そのままだと最初から押し合って弾けるため。
- 2026-10-03 ねじを外せるかは、タップした瞬間の板の姿勢で調べる（揺れている途中でも、見たままで判定する）。落ち着くまで待たせると、続けて外す手触りが悪くなるため。
- 2026-10-03 詰みは、固定の板（ねじ2本以上）だけが隠すとみなした楽観的な判定で決める。ぶら下がった板や落ちて止まった板は回せばどけられるかもしれないので、それらに隠れているだけなら詰みにしない。固定の板は動かないので、この判定で詰みなら本当に詰み。
- 2026-10-03 物理は 1/60 秒の固定の刻みで進め、1フレームに最大4刻み。遅い端末ではゆっくり動くが、結果は刻みの数と操作の順で決まる。速さと回る速さが小さい刻みが 0.5 秒続いた板は落ち着いたとみなし、全部落ち着けば刻みを止める（Rapier の sleep() で眠らせると、軸でつないだ板が起きたときに軸が外れたため、眠らせはしない）。
- 2026-10-03 板の摩擦は 0.8。最初の斜めの見た目（約 26 度）で、天板に落ちた札が滑り出さずに止まるようにするため。
- 2026-10-03 解ける保証の探索の隠れ判定（`src/safe.js`）は、ぶら下がった板を「固定の板に当たるまで回れる弧のどこにいてもよい」とみなし、その範囲全部で隠す。回る範囲は 15 度刻みで調べ、当たる角度は二分法で詰め、刻みの間は両端の姿勢の凸包を弧のふくらみ（矢高）だけ太らせて含める。ぶら下がった板どうしは当たらないとみなす（範囲が広がる側）。
- 2026-10-03 最後のねじを外す手は、外した板が抜け出せるときだけ許す。抜け出せる = 弧のどの姿勢からでも、軸の6方向（と板の法線の向き）のどれかへまっすぐ動かして、残った板（固定の形とぶら下がった板の届く範囲）に当たらない。抜け出した板は何も隠さないとみなす。落ちた板がどこに止まるかは物理しだいで見積もれないので、閉じ込められる板を作る手そのものを選ばない。前提の遊び方は「板を外したら傾けて落とし切る」。
- 2026-10-03 板の法線の向きへ抜け出せるかは、板の厚みの外側（今いない所）だけを調べる。面の中の弧は隣の板に触れるところまで広がるので、まるごと掃くと壁の板がどれも「出られない」になるため。
- 2026-10-03 見積もりが物理より甘くないことは、生成した盤面の手順を物理つきで再生し、どの場面でも「物理で隠れているねじは見積もりでも隠れている」「外した板は傾ければ落ちきる」を調べて確かめる（`test/safe-physics.test.js`、手元で 1〜1000 のシード）。理屈だけで保証せず、物理と突き合わせる。
- 2026-10-03 盤面の生成器（`src/generator.js`）は、軸に沿った板だけで箱・本棚・机を組む。板の向きを軸にそろえると、抜け出す向きが6方向で足り、見た目も家具らしくなるため。札（外側の面に載せた小さな板）と、中の棚板・仕切りで「回して探す」「外すと見える」を作る。
- 2026-10-03 色は、先に色なしで外せる順番を探し、その順番を下敷きに箱の色の並びを窓の中で混ぜて割り当て、色つきで手順を探して確かめる（2D 版の assignColors と同じ）。見つからなければ順番どおりに箱が埋まる割り当てにする（その順番で必ず解ける）。
- 2026-10-03 板の頂点を縮めるとき（`plateVertices` の shrink）は、輪郭の各辺を同じ幅だけ内側へ動かす。重心へ向けて縮める形だと、細長い板の短い向きがほとんど縮まず、物理の当たりの形（縮めてから角を丸める）が実物より太って、壁の間の棚板が挟まって落ちなかったため（M5 の物理にも効く直し）。
- 2026-10-03 生成した盤面は `?seed=番号`（と `&kind=box|shelf|table`）で開ける。ステージの進行（M7）までの確かめ用で、既定は固定の箱のまま。
- 2026-10-03 ステージの盤面は、ステージ番号から生成器の設定（形・色の数・札の数・色の混ぜ方・板1枚のねじの上限）を決めて、その場で作る（`src/stages.js`）。盤面を保存して配らないので、dist が軽く、何ステージでも続けられる。シードはステージ番号 × 1000 から順に試し、ステージごとの条件（ねじの数の範囲、札で隠れたねじがある、など）に合う最初のものを使う。
- 2026-10-03 最初の 6 ステージは手で並べる: 1 は閉じた小さな箱（2 色・ねじ 12 本・隠れたねじ無し。見えている面を外し終えると、裏と底を回して探すことになる）、2〜3 は札で隠れたねじ、4 は中の仕切りか棚板、5 は本棚、6 は机。1つのステージで新しいことを1つだけ覚えるため。7 から先は箱・本棚・机を順に回し、色（4→6）、札（2→4）、ねじの数の下限、色の混ぜ方を数ステージごとに増やす。
- 2026-10-03 到達したステージは localStorage に1つの数として保存し、クリアした瞬間に書く（「次へ」を押す前に閉じても、次は続きから）。前のステージを遊び直しても到達は戻さない。保存できない端末でも、その回は進める。
- 2026-10-03 固定の箱（M3）は `?level=box` で開ける形に残す。物理の場面のスクリーンショット（M4・M5）がこの盤面の決まったねじを使うため。
- 2026-10-03 ステージ 1 は箱の色を交互にする（生成器の `alternate`）。2 色で出ている 2 箱がいつも違う色なら、どの順に外しても待機スロットに頼らずに済み、最初のステージで詰まない。
- 2026-10-03 物理の wasm は、Rapier の互換版（base64 埋め込み）のまま使い、ビルドのときだけ Vite のプラグイン（`vite.config.js`）で別ファイルの `.wasm` に取り出す。wasm を別にした版（`@dimforge/rapier3d-deterministic`）は wasm を ES モジュールとして import する形で、Vite・Node のテストの両方に追加の設定が要るため。バイト列は同じなので決定性は変わらず、テストは埋め込みのまま走る。JS は約 5MB → 0.8MB（gzip で 1.8MB → 0.2MB と wasm 1.2MB）。
- 2026-10-03 板が落ち着いたかは、速さに加えて「ある姿勢からほとんど離れないまま一定時間たったか」でも決める（0.5 秒で 0.02、3 秒で 0.5）。それでも動き続けるときは、最後に板の状態か重力の向きが変わってから 20 秒（1200 刻み）で刻みを止める。接触が震え続けたり、隣の板の間で数度の幅で揺れ続けたりする板が、描画と電池を使い続けていたため。
- 2026-10-03 画面は何かが変わったときだけ描き、何も動いていなければフレームの呼び出しも止める。DPR は 2 まで、2 以上の画面ではアンチエイリアスを切る。動かしている間のフレームの間隔が平均 24ms を超えたら、描く解像度を 2 → 1.5 → 1.25 → 1 と下げる（その回のあいだ戻さない）。中級機で滑らかに動かすため。
- 2026-10-03 ねじの形と材質は、大きさと色ごとに1つ作って使い回し、十字の溝は1つの形にまとめる（ねじ1本あたりの描く回数 4 → 3）。板はふだん不透明で描き、消えるときだけ透明にする。
- 2026-10-03 タップでねじを選ぶ半径は 32px（CSS、約 8.5mm。指の腹の幅）。1 ピクセルのドラッグで回る角度は、画面の短い辺をなぞると半回転になる値（短い辺は 320 以上とみなす）。固定の 0.01 では幅 390 の画面を横切ると 220 度回って行き過ぎたため。見失ったとき用に、右下に「向きを戻す」ボタン（0.35 秒かけて最初の向きと距離に戻す）。
- 2026-10-03 効果音は Web Audio でその場で合成する（音のファイルを持たない）。振動は navigator.vibrate（iPhone の Safari には無く、そのときは鳴らない）。音と振動は1つのボタンでまとめて入り切りし、端末に保存する。どの場面で何を鳴らすかは `src/feedback.js` の表にして、テストで抜けが無いことを確かめる。
- 2026-10-03 Android 版は Capacitor 8.5.2 で `dist/` をそのまま包む（`webDir: dist`）。2D 版と同じ道具・版なので、手元の PC のビルド環境をそのまま使える。公開ページと同じものを入れるので、Android だけの差し替えを持たない。`android/` はリポジトリに入れ、同梱のページ（`assets/public`）は入れない（`npm run app:web` が毎回写す）。
- 2026-10-03 アプリ ID は `io.github.shostako.screwpuzzle3d`、名前は「ねじ外し3D」。2D 版（`io.github.shostako.screwpuzzle`）と別のアプリとして並べて入れられるようにするため。
- 2026-10-03 安全域は Capacitor の SystemBars が入れる `--safe-area-inset-*` を先に使い、無ければ `env()`（2D 版と同じ）。Android の古い WebView では、端から端まで描く画面で `env()` が 0 を返すことがあるため。ブラウザではこれまでどおり `env()` が効く。
- 2026-10-03 外したねじは画面に常に1本だけ見せる。立体のねじが抜ける向きへ少し抜け（0.22 秒）、抜けきった瞬間に立体のねじを消して、同じ位置・同じ見かけの大きさの印に持ち替えて箱やスロットへ飛ばす。以前は抜ける立体のねじと飛ぶ印が同時に出て、1本が2方向へ外れて見えた（実機で指摘）。スクリーンショットのスクリプトで、両方が出たフレームが無いことを確かめる。
- 2026-10-03 見た目は「おもちゃブロック調」にする（ユーザーが3案から選んだ）。ねじの色が一番読みやすく、車・家・動物などへ題材を広げても合うため。似たアプリは木の板に色のねじが主流で、そちらより明るく軽い印象で差を付ける。
- 2026-10-03 ねじは六角穴付きボルト（キャップボルト）風のカラーにする（ユーザーの指定。金型の現場で見慣れた形）。比率は JIS B 1176 に寄せ、当たり判定の半径は変えず見た目だけ替える。
- 2026-10-03 マスコットは「ネジまる」（キャップボルトの子）。見本の絵はユーザーの PC の Codex（ChatGPT の枠、課金なし）で作り、three.js の基本形の組み合わせで立体に起こす。3D 生成 AI（Figma Weave）は MCP からの実行が有料プラン限定だったため使っていない。基本形で作れば外部の読み込みが要らず、表情や動きもコードで変えられる。
- 2026-10-03 色・材質・光・背景は `src/theme.js` の表（`THEME`）1か所で決める。HUD の CSS の色（`--red` など）も起動時にこの表から入れ、CSS とねじの色を二重に持たない。
- 2026-10-03 影は描かない（影の地図を作る分、毎フレームもう1回描くことになる）。空のグラデーション・白いマット・マットに落ちる影は CSS の背景で描き、キャンバスは透明にして重ねる。外れて落ちる板がマットを突き抜けて見えることもない。立体らしさは、起動時に1回だけ焼く映り込み（PMREM）と、半球光・主光・縁の光で出す。
- 2026-10-03 板の材質は艶のある MeshStandardMaterial（クリアコートの MeshPhysicalMaterial は使わない。見本より少し艶が浅いが、塗る量が軽い）。角の丸みは半径 0.18、縁の面取りは 0.06 で、外形は当たりの形と同じ大きさ。丸みで当たりの形より削れるのは角の 0.07 ほどなので、角でかすめて隠すねじも隠れて見える。輪郭の線はやめた（板1枚の描く回数 2 → 1）。
- 2026-10-03 キャップボルトは頭の半径 r（当たりの半径 0.3 のまま）を基準に、ねじ径 1.33r、頭の高さ 1.2r（JIS の k = d より少し低い）、六角穴の対辺 0.9r。頭は 0.3r 板に沈め（座ぐりに入っているように見える）、板から出るのは 0.9r = 0.27。札の厚み 0.3 の下に隠れたねじの頭が札を突き抜けないため。ねじ部は 0.6r で板の中に収め、箱の内側に突き出さない。描く回数はねじ1本 3 回のまま（頭・六角穴・ねじ部）。六角穴も当たり判定に入れる（頭の真ん中は穴が抜けているため）。
- 2026-10-03 分解の演出（D2）は見た目だけにし、ルール・隠れ判定・物理は変えない。板が外れたときに物理で弾き飛ばす案はやめた（ぶら下がった板や隣の板を押して、遊びの結果が変わるため）。はじけは板の Mesh を膨らませて光らせるだけ、盤面の外へ落ちた後だけ回しながら横へ流す。
- 2026-10-03 ねじは右ねじとして頭から見て反時計回りに、1回転でピッチ1つ分だけ抜く（金型屋の目で嘘が無いように）。以前は時計回りで、回り方と抜ける量が合っていなかった。
- 2026-10-03 箱のふた・着地のはずみ・ポンの輪・星は CSS で描き、3D の描く回数を増やさない。演出の時間と曲線は `src/effects.js` の表にまとめ、テストで長さ（1本 1.4 秒以内）と描く負荷（全ステージで板1・ねじ3回、三角形 8 万枚以内）を見張る。
- 2026-10-03 マットと影は、立体を包む球の見かけの大きさから CSS 変数で置く（D1 は画面の高さの割合で固定だった）。回すたびには動かさない（背景を毎フレーム描き直さないため）。
- 2026-10-03 マスコット（D3）は盤面とは別の小さなキャンバスと描き手（WebGLRenderer）で左下に描く。盤面は「変わったときだけ描く」ので、待機中も動くマスコットを同じキャンバスに入れると盤面まで毎フレーム描き直すことになるため。小さなキャンバスなので塗る量は少なく、待機中は 1/2 の間隔で描く。指の操作は下の盤面へ通す（`pointer-events: none`）。
